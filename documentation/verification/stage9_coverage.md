# Stage 9 coverage consolidation

Coverage-only consolidation reuses source-matched Stage 5, 6, and 8 evidence.
The versioned dictionary and migration map are generated by preparation at
`documentation/verification/stage9_bin_dictionary.csv` and
`documentation/verification/stage9_bin_migration.csv`. Per-test exports keep
XSim and Verilator separate under `reports/stage9_coverage/{xsim,verilator}`.
The export contains run provenance, long and wide bin data, applicable-test
denominators, and separate architectural and pipeline classes. Simulator code
coverage is reported as not collected. Failed, incomplete, unproven, duplicate,
unknown-bin, and configuration-mismatched observations are rejected.

`source_provenance_status` is a required field in each run row and prepared
source record. Its allowed values are `PASS` and
`DOCUMENTED_LIMITATION_RUNNER_SNAPSHOT_UNAVAILABLE`. `PASS` requires an empty
`unresolved_source_hashes` list; the limitation value requires at least one
unresolved hash. Missing or inconsistent status is invalid and is never
treated as `PASS`. Strict provenance closure and overall coverage closure are
computed from the verified observations and coverage gaps.

From Windows CMD, run `py -3 scripts\simulation\prepare_stage9.py` with the six
Stage 5/6/8 output and report arguments and
`--stage8-manifest sim_out_stage8_prepare_mem_footerfix/stage7/m_manifest.csv`, then run
`scripts\simulation\run_stage9_verilator.sh reports\stage9_coverage\prepared.json`
and `scripts\simulation\run_stage9_xsim.bat reports\stage9_coverage\prepared.json`.
Run the parser negative checks before either collector. The final manifest SHA256
is `c9952d362c4d045cfd98d65143e5b91a98a7f13f59e26f4906822c7fd3f9518f`.

Legacy Stage 3.5 and Stage 4 IDs are retained where per-test evidence supports
them; the migration CSV identifies coarsened and historical-only bins. Machine
fault/IRQ overlap is not targeted by the saved scenarios, and RVV, floating
point, and multi-hart ordering are outside the implemented design. These
classifications are not coverage hits. No functional RTL is changed.
